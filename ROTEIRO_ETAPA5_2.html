O que tem dentro

add_event — INSERT, já conhecida. query_events — SELECT com texto e datas em America/Sao_Paulo, no mesmo espírito de query_transactions. No fim: TOOLS_AGENDA = [add_event, query_events].

Este slide nasceu de um bug real, encontrado enquanto o professor testava. A tool add_event estava perfeita, o Postgres no ar, e ainda assim o Assessor respondia “registrei” sem gravar nada. O erro não estava no Python: estava no prompt.

O rastro do agente — leia a última linha

Pergunta: “tenho um evento na quinta às 15h, reunião com o Marcos”. O agente chamou query_events, viu o dia livre… e parou:

o que o agente fez ANTES da correção

NENHUMA chamada a add_event: {"dominio":"agenda","intencao":"criar", "resposta":"Posso criar 'Reunião com o Marcos' em 2026-09-24 15:00–16:00.", "recomendacao":"Confirmo o registro?"} # O orquestrador transformou isso numa frase afirmativa. # O usuário leu "salvei". O banco continuou vazio.

Por que ele fez isso? Porque nós ensinamos.

O AGENDA_SHOT_2 — o few-shot de criação de evento — era exatamente aquele texto: “Posso criar… Confirmo o registro?”. O exemplo mostrava o agente propondo o evento, nunca gravando. O modelo copiou o exemplo, como devia.

O que o prompt tinha

  • Shot de criar sem nenhuma chamada de tool
  • Sem campo escrita na saída — nada para carregar o id do banco
  • Nenhuma regra proibindo dizer “registrei” sem retorno
  • Comparem: o FINANCEIRO_SHOT_2 já trazia "escrita":{"operacao":"adicionar","id":...}

O que passa a ter

  • Seção GRAVAÇÃO com o fluxo obrigatório de 4 passos
  • Campo escrita com id real e google:"ok|falhou"
  • Regra: só afirmar registro se add_event devolveu status:"ok"
  • Shots 1, 2 e 3 reescritos mostrando as tool calls
app/prompts.py — bloco novo, dentro de AGENDA_PROMPT (depois de ### REGRAS)
colarClique para ver
### GRAVAÇÃO — LEIA ANTES DE RESPONDER "criar" Se o usuário informar um compromisso ("tenho reunião quinta às 15h", "marca X amanhã"), isso JÁ É a ordem de registrar. NÃO pergunte "confirmo o registro?": chame `add_event` na mesma resposta. Você só pode escrever no campo "resposta" que o evento foi registrado se `add_event` tiver devolvido `status: "ok"` com um `id`. Sem esse retorno, o evento NÃO existe no banco — dizer que existe é mentir para o usuário. Fluxo obrigatório ao criar: 1. `query_events` no dia pedido (checar conflito). 2. `add_event` com o `start_time` em ISO 8601 COM fuso (ex.: 2026-09-24T15:00:00-03:00). 3. `add_google_event` com os mesmos dados. 4. JSON final com "escrita":{{"operacao":"adicionar","id":<id devolvido>}}. Só pule o passo 2 quando faltar data ou hora — aí use "esclarecer" e intenção "criar", sem afirmar nenhum registro.
Atenção às chaves duplas

AGENDA_PROMPT é uma f-string. Todo { literal de JSON tem que virar {{ e } virar }}, senão o Python tenta interpretar como campo de formatação e o import quebra. Isso vale para o bloco acima e para o campo escrita.

A lição que vale mais que o código

Few-shot não é decoração, é comportamento. O modelo imita o formato e a sequência de ações do exemplo. Se o exemplo não chama tool, o modelo não chama tool — por mais que a seção TAREFAS mande registrar. Instrução em prosa perde de exemplo concreto.

E o pior tipo de bug apareceu aqui: silencioso. Nada de exceção, nada de traceback, log limpo. Só o usuário acreditando que tem uma reunião marcada. Peça para a turma conferir o banco, não a resposta do chat.

teoria · produto

Num app de verdade, quem é o usuário?

Imaginem o Assessor no ar, com mil contas. Um único servidor FastAPI atende todo mundo. O calendário de cada pessoa é o Gmail dela. A máquina deixa de identificar o aluno — o login identifica.

1Login no AssessorO usuário entra com e-mail/senha ou Google. O backend emite um JWT / sessão. Cada request carrega user_id.
2Conectar o CalendarUm botão “Vincular Google”. O browser abre o OAuth da Google (tipo Web, com redirect URI do Assessor). A pessoa autoriza.
3Token no servidorO Assessor guarda access_token + refresh_token daquela pessoa no banco, criptografados. Nunca no notebook do usuário.
Quando o usuário diz “marca reunião”O que o backend faz
1. IdentidadeLê o JWT. Sabe que é a Maria, não o João.
2. Banco próprioChama add_event no Postgres dela (ou com user_id na linha).
3. Calendário delaPega o token da Maria e chama o MCP (oficial, HTTP) com Authorization: Bearer ….
4. IsolamentoO João, no mesmo servidor, nunca vê o token da Maria. Trocar de máquina não muda nada.
Duas identidades, sempre

O projeto no Google Cloud é o RG do aplicativo (um só, da empresa). O OAuth no navegador é o RG da pessoa. Sem o primeiro, a Google não sabe quem está pedindo acesso. Sem o segundo, ela não sabe de quem é o calendário. Isso não muda na aula — só muda onde o token mora.

O que a aula NÃO vai implementar

JWT, tabela de tokens, cliente OAuth tipo Web, callback /oauth2callback, refresh automático. Dá para fazer — e é o caminho de um produto. Não cabe numa aula de MCP. A gente simula o mesmo contrato com um atalho: cada notebook é um usuário.

Antes de escrever código: pergunte ao servidor

O melhor jeito de acreditar que MCP não é mágica é falar com o servidor da Google na mão. Um POST. Sem SDK, sem token, sem instalar nada. Neste servidor, o tools/list responde sem autenticação: é o catálogo, não os dados.

PowerShell — Python, para o JSON não quebrar
ao vivo na aulaClique para ver
python -c "import httpx; r=httpx.post('https://calendarmcp.googleapis.com/mcp/v1', headers={'content-type':'application/json','accept':'application/json, text/event-stream'}, json={'jsonrpc':'2.0','id':1,'method':'tools/list'}); print([t['name'] for t in r.json()['result']['tools']])"
Não use curl no PowerShell

No Windows, curl é apelido de Invoke-WebRequest. As aspas do JSON se perdem e a Google responde -32700 JSON Parse error. O comando acima manda o JSON certo. Se quiser curl de verdade: curl.exe e o corpo em um arquivo .json.

Agora tente CHAMAR sem token

Neste servidor da Google, tools/list pode ser chamado sem autenticação, enquanto executar operações sobre o calendário exige OAuth. Isso é uma decisão do servidor; o MCP não obriga tools/list a ser público.

Na prática: um tools/call sem Bearer devolve 401 no HTTP — falta de credencial na camada de transporte. isError é outra coisa: aparece no resultado de uma chamada MCP já autenticada (ou rejeitada pelo servidor MCP). Não misture as duas camadas.

stdio existe — é assim que o Cursor fala com o mcp_server.py de vocês. A aula do Calendar, porém, fica no HTTP: o aluno já tem Python, e o servidor oficial da Google é uma URL.

Na aula o caminho é Python

O tools/list oficial (slide anterior) mostra o contrato sem login. O login é autenticar() em Python. A gravação tenta o MCP oficial e, se o serviço MCP não estiver ligado no Cloud, usa a Calendar API com o mesmo token. Nenhum dos dois instala Node.

O que isso ensina

Trocar de transporte não muda o handshake: initialize, call_tool, ler o resultado. Só muda quem entrega os bytes. O código da aula, daqui para a frente, usa só HTTP. O @cocal fica neste slide — exemplo de servidor MCP em Node + stdio, não dependência da turma.

Cuidado com “MCP é plug and play”. Dois servidores podem criar o mesmo evento com contratos diferentes — por isso o tools/list vem antes do cliente:

bloco B · como se escreve

O que o cliente faz, em quatro passos

Não é mágica. O arquivo calendario_google.py só faz isto, nesta ordem, quando o agente chama add_google_event:

1Loginautenticar() já abriu o Chrome uma vez. O token fica em google-calendar.token.json.
2HandshakeAbre uma sessão HTTP com a URL da Google e manda initialize — o “olá” do protocolo MCP.

Por que existe o passo 4

O catálogo (tools/list) responde sem ligar nada no Cloud. Gravar pelo MCP oficial exige o serviço Calendar MCP API, ainda em preview. Sem ele a Google devolve 403. A Calendar API clássica já está ligada no projeto do professor: o mesmo token OAuth cria o evento lá. Os dois caminhos são HTTP em Python.

Erro do Google não derruba o banco

Se 2, 3 e 4 falharem, a tool devolve {"status":"error", ...} — não levanta exceção. O add_event já gravou no Postgres. Tool que fala com a internet devolve erro, não levanta erro.
